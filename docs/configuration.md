# Configuration

All editable portfolio settings and content live in `src/portfolio/`. Start there when adapting the template:

```text
src/portfolio/
  config.ts        identity, section order, limits and shader settings
  seo.ts           descriptions, keywords and social preview defaults
  publications.ts  external articles and publisher names
  sections/        text and entries for each homepage section
  posts/           local .svx articles
  cache/tweets.json  generated by pnpm tweets:sync
```

`src/lib/` contains implementation: components, types, validation and data loading. You do not need to edit it to update portfolio content. Public images and files stay in SvelteKit's standard `static/` directory; secrets stay in environment variables.

## Public settings

`src/portfolio/config.ts` is the entry point. It is typed for editor completion and validated by `pnpm config:check`, `pnpm dev`, `pnpm check` and `pnpm build`.

| Setting                     | Used by                                                           |
| --------------------------- | ----------------------------------------------------------------- |
| `name`                      | Hero, avatar fallback, default SEO, copyright and structured data |
| `role`                      | Hero and default SEO                                              |
| `url`                       | Canonical URLs, social previews, sitemap and robots               |
| `language`, `locale`        | HTML/structured-data language and Open Graph locale               |
| `githubUsername`            | Contribution API, GitHub social link and structured data          |
| `xHandle`                   | X social link, Twitter metadata and structured data; omit `@`     |
| `linkedInUrl`, `resumeHref` | Footer links; an empty string removes a link                      |
| `sections`                  | Ordered homepage sections; remove an ID to hide it                |
| `writing.limit`             | Number of combined local/external entries; zero hides Writing     |
| `hero.shader`               | Shader visibility, scale, blur, grain and chromatic aberration    |

The hero and footer frame the homepage and are outside the reorderable section list. Empty About, Experience, Projects, Writing and Testimonials sections are skipped with their separators. Hiding GitHub skips its homepage request. Hiding Contact also disables its POST endpoint.

```ts
sections: ["about", "projects", "writing", "contact"],
writing: { limit: 5 },
```

Names and descriptions inside articles, experience entries and project copy remain editorial content. Review them when adapting the template. `language` selects metadata, not automatic translation; edit labels and article text separately.

## Section content

Each file in `src/portfolio/sections/` owns a small set of content:

- `hero.ts`: avatar source and description.
- `about.ts`: paragraphs, links and nested list content.
- `experience.ts`: employment entries, logos, technologies and highlights.
- `projects.ts`: projects and action labels.
- `writing.ts`: section heading and local-article action label.
- `testimonials.ts`: X post IDs and section title.
- `github.ts`: graph labels; username comes from `portfolio`.
- `contact.ts`: form labels and feedback copy.
- `footer.ts`, `socials.ts`: footer copy and derived social links.

SEO copy lives one level up in `src/portfolio/seo.ts`; external publications and service names live in `src/portfolio/publications.ts`.

These files use `HomepageContent` and item types from `src/lib/types/portfolio.ts`. Runtime validation covers public settings, article metadata, external URLs/sources and testimonial IDs. TypeScript checks the section data shapes; it cannot check whether remote links exist or whether your prose is correct.

## Assets and visual settings

Keep public images and documents in `static/`, referenced with root-relative URLs such as `/images/avatar.webp`. Replace:

- `static/images/avatar.webp` and experience logos used by `experience.ts`;
- `static/favicon.svg`;
- `static/resume.pdf` and, if used, its source in `resume/resume.tex`;
- `src/lib/assets/hex-logo.svg`, used by Open Graph images.

The current font is self-hosted Inter. Font declarations and the regular-font preload live in `src/app.html`; font stacks and theme tokens live in `src/routes/layout.css`. OG font loading lives in `src/lib/seo/og-image.ts`. Update all three if changing fonts. `src/lib/seo/og-theme.ts` owns the OG palette.

`LiquidGlass` is feature code under `src/lib/features/hero/components/`, separate from shadcn primitives. Hero colors come from CSS theme tokens and are converted to six-digit HEX for the shader. Its scale range is 0.35–2.5. Turning it off retains the existing hero card and avatar layout. Its `pixi.js/unsafe-eval` import installs Pixi's CSP-compatible implementation (despite the name, it avoids dynamic code evaluation); keep it when updating the copied shader.

## Integrations and secrets

Never put credentials in `src/portfolio/`. Copy `.env.example` to `.env.local` for Vite development. The values stay on the server except `PUBLIC_TURNSTILE_SITE_KEY`, which is intentionally public.

| Variable                    | Requirement                                                        |
| --------------------------- | ------------------------------------------------------------------ |
| `GITHUB_TOKEN`              | Optional; enables live GitHub contributions                        |
| `RESEND_API_KEY`            | Required to send contact messages                                  |
| `CONTACT_TO_EMAIL`          | Contact inbox                                                      |
| `CONTACT_FROM_EMAIL`        | Verified sender; development default is Resend's onboarding sender |
| `PUBLIC_TURNSTILE_SITE_KEY` | Turnstile site key for the browser                                 |
| `TURNSTILE_SECRET_KEY`      | Turnstile verification secret for the server                       |

Use the Turnstile action `contact_form`. Missing mail or anti-bot settings do not disable validation; the endpoint returns a service configuration error. Remove `contact` from `sections` if the form is not part of your portfolio.

For a local Worker preview, use Wrangler's `.dev.vars` or its configured environment. For deployment, set variables/secrets on Cloudflare. `pnpm setup:check` checks local configuration only and never prints secret values or sends a message.

```sh
pnpm exec wrangler secret put GITHUB_TOKEN
pnpm exec wrangler secret put RESEND_API_KEY
pnpm exec wrangler secret put CONTACT_TO_EMAIL
pnpm exec wrangler secret put CONTACT_FROM_EMAIL
pnpm exec wrangler secret put TURNSTILE_SECRET_KEY
```

Set `PUBLIC_TURNSTILE_SITE_KEY` in the Worker's environment as well. Run `pnpm build` before `pnpm preview` or `pnpm deploy`; those commands use the existing build output.

## Testimonials

1. Add numeric post IDs to `testimonials.ts` in the desired order.
2. Run `pnpm tweets:sync`.
3. Review and commit `src/portfolio/cache/tweets.json`.

Normal builds and development startup never contact X. Sync has request timeouts, keeps cached posts on failures and exits with a failure status if any post could not refresh. Removed IDs no longer appear even if an old cache still contains them. Clear the IDs or remove the section to omit testimonials.
